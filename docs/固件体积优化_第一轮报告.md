# 固件体积优化_第一轮报告

完成度审计见 `docs/第一轮完成度审计.md`；验收项与证据逐项矩阵见 `docs/第一轮验收矩阵.md`；当前优化镜像 OTA 交接清单见 `docs/当前优化镜像OTA闭环交接清单.md`。

## 优化目标

在不修改 Boot/APP/APROM/OTABAKROM 分区地址、不删除 OTA/CRC/Boot 校验链路的前提下，为 APP 固件释放 Flash 余量。APP 起始地址保持 `0x08008000`，APP 最大空间约 `0x1C000`，即 112 KB。

Release-MinSize 最终 Total ROM Size 为 69.97 KB，低于 85-90 KB 目标区间。

## 主要变化

- 新增 Keil `Release-MinSize` target；`program` target 保留为 Debug/logging/full-feature path。
- Release-MinSize 加入日志、OTA 调试、旧链路、日出日落和 BL0942 浮点补偿开关。
- `main.c`、`sys_tick.c`、`stm32f1xx_it.c`、`hw_uart3.c` 按 `APP_LOG_ENABLE || APP_OTA_LOG_ENABLE` 关闭 APP UART3 日志链路。
- `hw_uart3.o` 在 Release-MinSize 中贡献变为 0，`main.o` 不再引用 `hw_uart3_init`、`hw_uart3_process`、`dma_printf`。
- `ota.o` ROM 从 12944 降到 6261 bytes，Release map 中不再分配 `dma_printf` 相关路径。
- `mqtt_zk_protocol.o` ROM 从 14191 降到 11523 bytes。
- `nbdriver.o` ROM 从 8233 降到 5532 bytes。
- `app.o` 从 31 bytes 降到 0，`protocol.o` 保持 0。
- Release-MinSize 关闭设备端日出日落天文计算，普通计划任务仍保留；日出日落需求在本轮策略下需要平台侧先换算为普通具体时间点后再下发执行。
- Release-MinSize 关闭 BL0942 浮点版 X 电容补偿，改走整数/定点补偿路径。

## 旧链路状态

已全局审计 `appProcess`、`uploadAllDataPoint`、`uploadDriverDataPoint`、`uploadDriverOnedataPoint`、`uploadfaultListDataPoint`、`Offline_report`、`initUploadDataPoint`、`addIntTypeDataPoint`、`addFaultListDataPoint`、`finishUploadDataPoint`、`sendTcpData` 及旧参数/OTA入口。Release map 中旧 `sendTcpData` 出现在 `Removing ...` 段；`App.c`、`Protocol.c` 主体通过宏关闭，未进入最终镜像。

仍保留的功能入口：中科 MQTT JSON 协议、计划任务普通时间点、参数配置、RTC 配置、BL0942 计量、NTC、raw TCP OTA 状态机、Boot 校验相关写入。

## OTA 路径

Release-MinSize 保留 raw TCP OTA 主链路，关闭 UART OTA 日志和旧调试路径。`OTA_USE_QHTTPREADFILE_UFS=0`，`OTA_RAW_HEX_LOG_ENABLE=0`，`OTA_DEBUG_DOWNLOAD_ONLY=0`，`OTA_STREAM_TO_BACKUP_DEBUG=0`，`OTA_DEBUG_CLEAR_ALL_UFS=0`。QHTTPREADFILE/UFS 诊断变量只在日志或旧路径开启时编译。

## 数学库

`powf/sqrtf/sinf/cosf/tanf/acosf/asinf/fmodf` 没有分配到 Release-MinSize 最终镜像。`zk_sunriset.c` 文件级受 `ZK_ENABLE_SUNRISE_PLAN` 保护，Release 下仅剩 removed/ABSOLUTE 元信息。`scanf_fp.o` 仍贡献 878 bytes，来源是 cJSON 数字处理，按“本轮不大改 cJSON”原则暂不处理。

## cJSON 统计

cJSON 仍同时服务接收 JSON 和发送 JSON：

- 发送 JSON：`mqtt_zk_protocol.c` 的登录、心跳、运行上报、告警、OTA 回执；`zk_property.c` 的属性读写响应；`zk_work_plan.c` 的计划读写响应。
- 接收 JSON：`Json_Protocol.c::app_mqtt_rx` 负责解析 MQTT 下行并分发到 `mqtt_zk_protocol.c`，再进入属性、控制、计划、OTA 等处理。
- 后续轻量化建议：新增 `zk_json_writer.c/.h`，先替换发送 JSON；接收 JSON 暂保留 cJSON，稳定后再替换接收侧。
