# 1. 阶段门禁

每个阶段按以下顺序推进：

```text
基线确认
 -> 修改清单和风险审查
 -> 代码实施
 -> 独立代码/Flash审查
 -> Mac主机测试和ARM GCC源级检查
 -> Keil Debug/Release fresh rebuild
 -> MAP/ROM/RAM/Warning审计
 -> 需要硬件行为时执行J-Link/串口/MQTT实机验证
 -> 阶段验收
 -> 才允许进入下一阶段
```

门禁规则：

1. 主机测试不能替代 Keil 编译；
2. Keil 编译不能替代 J-Link 烧录和回读；
3. J-Link 回读不能替代带载、MQTT、OTA、保护和长稳测试；
4. 任何 Flash 地址、长度、Target IROM 或 Boot 契约变化立即阻断；
5. 旧文件只能在阶段 8 且满足总文档第 25.4 节全部删除条件后删除；
6. 阶段失败不得通过屏蔽功能、关闭校验或跳过测试进入下一阶段。

# 2. Flash 布局不可变基线

所有区间均使用半开区间 `[start, end)` 表示：

| 区域 | 起始地址 | 结束地址（不含） | 容量 | 阶段 1-8 规则 |
| --- | --- | --- | ---: | --- |
| Boot | `0x08000000` | `0x08005000` | 20 KiB | APP 重构不修改 |
| 参数主区 | `0x08005000` | `0x08006800` | 6 KiB | 地址和现有记录兼容不变 |
| 参数备区 | `0x08006800` | `0x08008000` | 6 KiB | 地址和现有记录兼容不变 |
| APP | `0x08008000` | `0x08024000` | 112 KiB | 两个 Target 均保持 |
| OTA 备份区 | `0x08024000` | `0x08040000` | 112 KiB | 地址、容量和 Boot 迁移契约不变 |

当前两个 Keil Target 的共同边界：

- IROM：`0x08008000`，长度 `0x0001C000`；
- IRAM：`0x20000000`，长度 `0x0000C000`；
- 必须定义 `APROM_OFFSET`；
- `SCB->VTOR` 必须指向 `0x08008000`；
- APP 镜像最高地址必须严格小于 `0x08024000`。

当前 Target 名称仍为 `program` / `Release-MinSize`，且两者仍存在旧业务宏差异；这不是总文档要求的最终 `IntegratedPower_Debug` / `IntegratedPower_Release` 形态。阶段 1 为避免同时破坏已有构建脚本暂不重命名，后续必须先修订构建/烧录工具契约，再统一名称和业务逻辑。

参数页中的现有记录：

| 记录 | 主区 | 备区 | 保留空间 |
| --- | --- | --- | ---: |
| `sys_data` | `0x08005000` | `0x08006800` | 首个 2 KiB 页内 |
| 中科属性页 | `0x08005800` | `0x08007000` | 第二个 2 KiB 页 |
| 运行统计 | `0x08005A00` | `0x08007200` | 从属性页偏移 `0x200` |
| OTA 结果 | `0x08005B00` | `0x08007300` | 从属性页偏移 `0x300` |
| 能量记录 | `0x08005B40` | `0x08007340` | 每槽 `0x40` |
| 电流/计量校准 V2 | `0x08005C00` | `0x08007400` | 每槽 `0x100`，当前记录 240 B |
| 工作计划 | `0x08006000` | `0x08007800` | 每区第三个 2 KiB 页，现有打包记录约 660 B |

注意：

- `Core/Src/flash_allocation.h` 中 `0x0801E000..0x08020000` 位于 APP 区内，属于必须先确认是否仍被正式目标引用的高风险历史布局；在确认和迁移前不得启用或写入。
- 阶段 1 不允许修改上述任何地址、记录大小、CRC、序号、主备选择或写入语义。
