### 4.1 Flash 存储布局

```
┌─────────────────────────────────────────────────────────┐
│                  zk_plan_store_t (Flash Page)             │
├──────────┬──────────┬──────────┬──────────┬──────────────┤
│  magic   │ version  │   size   │ checksum │  reserved    │
│  4 bytes │ 2 bytes  │ 2 bytes  │ 2 bytes  │  2 bytes     │
│0x5A4B504C│    1     │  1232    │  CRC16   │     0        │

│              plans[0]  ...  plans[7]                      │

└─────────────────────────────────────────────────────────┘
                       ▲
          ┌────────────┴────────────┐
          │                         │
   MAIN_ADDR                  BACKUP_ADDR
   0x08006000                 0x08007800

### 4.2 单条计划记录结构

```
zk_plan_record_t (packed, ZK_PLAN_MAX_JOBS=2)
┌─────────┬─────────┬─────────┬─────────┬─────────┬───────────┬──────────┬──────────┐
│ valid   │   en    │   id    │  type   │priority │ week_mask │job_count │ reserved │
│ u8      │ u8      │ u8      │ u8      │ u8      │ u8        │ u8       │ u8       │
├─────────┴─────────┴─────────┴─────────┴─────────┴───────────┴──────────┴──────────┤
│                         start (zk_plan_datetime_t)                                  │
│                year(u16) mon(u8) day(u8) hour(u8) min(u8) sec(u8) res(u8)          │
├────────────────────────────────────────────────────────────────────────────────────┤
│                          end (zk_plan_datetime_t)                                   │
├────────────────────────────────────────────────────────────────────────────────────┤
│                       jobs[0] (zk_plan_job_t)                                       │
│    cns_mask(u8) timetp(u8) action_count(u8) reserved(u8)                           │
│    actions[0..5]: minute(u16) bri(u8) reserved(u8) × 6                             │
├────────────────────────────────────────────────────────────────────────────────────┤
│                       jobs[1] (zk_plan_job_t)                                       │
└────────────────────────────────────────────────────────────────────────────────────┘

zk_plan_action_t (packed)
┌──────────┬─────────┬──────────┐
│  minute  │   bri   │ reserved │
│   u16    │   u8    │   u8     │
└──────────┴─────────┴──────────┘
```

结构体通过 `ZK_PLAN_MAX_JOBS` 和 `ZK_PLAN_MAX_ACTIONS` 宏统一控制数组大小，当前配置为最多 8 条计划 × 2 个时段 × 6 个动作点。

所有结构体均已添加 `__attribute__((packed))`，确保跨编译器版本的二进制兼容性。

## 五、存储可靠性设计

```
写流程:
  zk_plan_save_store()
    │
    ├─▶ 双份写入 (MAIN + BACKUP)
    │     hw_flash_write_bytes(MAIN_ADDR, ...)
    │     hw_flash_write_bytes(BACKUP_ADDR, ...)
    │
    └─▶ 写后读校验 (Read-back Verify)
          zk_plan_addr_valid(MAIN) || zk_plan_addr_valid(BACKUP)
          ── 至少一份写入成功才返回 BOOL_TRUE

读流程 (上电初始化):
  zk_work_plan_init()
    │
    ├─▶ 优先读 MAIN → 校验 (magic + version + size + checksum)
    │     └─ 通过 → 加载到 RAM (zk_plan_store)
    │
    ├─▶ MAIN 失败 → 读 BACKUP → 校验
    │     └─ 通过 → 加载到 RAM
    │
    └─▶ 双份都失败 → zk_plan_reset_store() → 初始化为空库

校验和算法:
  初始种子: 0x5A
  遍历范围: 整个 store (跳过 checksum 字段自身的 offset 8~9)
  算法: 逐字节累加 (16-bit wrapping add)
```

**评估**: 双页镜像 + 写后读校验 + 上电自动恢复，是一个经典的嵌入式 Flash 存储可靠性方案。即使写入过程中断电，最多丢失本次写入的数据，不会导致历史数据全部损坏。

## 六、协议合规性对照

### 6.1 计划下发 (7.4)

```
请求: {"CT":"W", "DT":{"plan":{...}}}
        代码: CT=W 路径 → zk_plan_upsert()          ✅ 一致

响应: {"CT":"W", "DT":{"err":N}}
        代码: zk_publish_error_response()            ✅ 一致
```

**JSON 字段校验矩阵**:

| 协议字段 | 代码校验规则                                        | 错误码 |
| -------- | --------------------------------------------------- | :----: |
| id       | 必填, 1~8 整数                                      | 3/5/2 |
| en       | 必填, 0 或 1                                        | 3/5/2 |
| type     | en=1时必填, 仅支持1                                 | 1/5/2 |
| priority | en=1时必填, 1~8 整数                                | 3/5/2 |
| sDate    | en=1时必填, "YYYY-MM-DD HH:MM:SS" (支持FFFF年循环)  | 3/5/2/8 |
| eDate    | en=1时必填, 同sDate, 且≥sDate(非年循环时)           | 3/5/2/8/9 |
| week     | en=1时必填, 7位 "0"/"1" 字符串                      | 3/5/2/8 |
| jobs     | en=1时必填, 数组1~2元素                             | 5/2/7/6 |
| jobs[].cns | 必填, 数组1~2元素, 值1~2                          | 5/2/7/6/3 |
| jobs[].timetp | 可选, 仅支持0                                   | 1/2     |
| jobs[].time | 必填, 字符串数组 "HH:MM"                         | 5/2/7/6/3/8 |
| jobs[].bri  | 必填, 整数数组, 0或10~100                         | 5/2/7/6/3 |

**en=0 语义**: 协议 7.4.5 规定 "当en=0时，其他字段可省略"，设计意图是保留配置仅关停。代码已实现：当 en=0 时，从 Flash 中读取已有记录，仅将 en 置 0，其余字段保持不变。

### 6.2 计划删除 (7.13)

```

### 6.3 当前运行计划查询 (7.9)

```
协议规定 (7.9.2):
  请求: {"CT":"R", "DT":{"now":cns}}

代码实现:
  DT.now = cns (Number) → zk_plan_find_current_match_for_cns(&match, cns)
  → 返回完整 plan 对象                                   ✅ 一致

协议规定 (7.9.3):
  响应: 完整 plan 对象 (含 en/id/type/priority/sDate/eDate/week/jobs)

代码实现:
  zk_plan_record_to_json() → 返回完整 plan JSON           ✅ 一致
```
