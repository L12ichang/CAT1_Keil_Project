# CAT1 量产校准固件开发方案

- 状态：实施基线（规划任务可补充细节，但不得放宽安全与验收门槛）
- 日期：2026-08-04
- 适用仓库：`/Users/mac/Desktop/CAT1_Keil_Project`
- 对接仓库：`/Users/mac/Desktop/tc`
- 目标产品：首期 50W，架构兼容 100W

## 1. 目标与完成定义

在不改变现有正常调光、保护、巡检、OTA 和属性读写行为的前提下，为 CAT1 电源增加一条受控的 MQTT 量产校准链路，使 `tc` 校准工作台能够：

1. 识别设备、硬件型号和校准能力；
2. 独占进入有租约的校准模式；
3. 设置 11 个协议等级并读取同一采样周期的原始数据；
4. 临时装载、校验、回读并提交现有协议定义的校准配置；
5. 掉电重启后读取同一版本和 CRC 的配置；
6. 在任何异常路径下关断输出并退出校准状态。

只有同时满足“命令 ACK、匹配回读、独立标准仪器验证、掉电重启回读”才可标记为校准成功。仅收到 MQTT、仅写入 Flash、仅通过主机测试或仅生成配置文件均不算完成。

## 2. 已确认的工程输入

### 2.1 产品与硬件

| 项目 | 50W | 100W | 结论 |
|---|---:|---:|---|
| 功率板拓扑 | 与 100W 共用 | 与 50W 共用 | 除 Y 电容接线方式外一致 |
| 输出电流采样电阻 RS3 | 120mΩ | 50mΩ | 以各自 BOM 为准，配置不可混用 |
| 输出范围 | 36–56V | 待锁定 | 50W 已确认 |
| 恒流额定值 | 890mA 默认出厂值 | 待锁定 | 50W 在 56V 时约 49.84W |
| MID | 1 | 待锁定 | 50W 已确认 |

量产载板使用 `DL-Cat.1-V1.0 2024.9.11`。已核对的关键链路：

- 输入电流：`RCSL1=10mΩ -> ACL_CS± -> 1k/33nF -> BL0942 IP/IN`；
- 输入电压：`4 × 430kΩ = 1.72MΩ -> 750Ω/33nF -> BL0942 VP`；
- 输出电压：`VO -> 39kΩ/750Ω -> 100nF -> Vo-VS`，标称换算比约 53；
- 输出电流：`RS3 -> LM2904`，标称增益约 8.333，再经 `1kΩ/100nF -> Io-VS`；
- MCU：`Vo-VS -> PB1/ADC_IN9`，`Io-VS -> PA6/ADC_IN6`；
- BL0942 通信：USART2，4800 8N1。

### 2.2 协议、等级与精度

- 仪器协议与实际 LED 综合测试仪、电子负载一致；
- 电源校准遵循现有 11 点协议，等级 `0/20/40/.../200` 对应实际输出 `0%/10%/20%/.../100%`；
- 50W 的 11 个目标恒流值为 `0/89/178/267/356/445/534/623/712/801/890mA`；
- 输出百分比 `<=30%` 的控制与采样相对误差门槛为 `<=2%`；
- 输出百分比 `>30%` 的控制与采样相对误差门槛为 `<=1%`；
- 0% 点不能用相对误差判定，必须在实施前配置绝对残余电流、残余电压和关断时间门槛；
- 11 个协议点用于拟合/存储，建议用 `5%/15%/.../95%` 十个中点做独立验证，不得把验证点重新并入拟合后再宣称通过。

## 3. 当前代码现状与真正缺口

### 3.1 已存在

- BL0942 已有全量读取命令 `58 AA`，周期性接收 23 字节帧；
- 已能得到输入电压、输入电流、输入功率等换算值并通过 `EleInfo` 上报；
- 输出电压/电流 ADC 已采样，当前换算分别使用约 53 倍分压比和 `OUTPUT_CUR_SENSOR × 8.34` 参数；
- 50W 当前回退参数包括 `MID=1`、`SET_OUTCUR=890`、`OUTPUT_CUR_SENSOR=120`；
- 已有 MQTT JSON 信封、属性主备保存、命令 ACK 和属性回读基础设施。

### 3.2 缺口

1. `EleInfo` 是工程值，不足以在 1%/2% 门槛下建立可靠的 Raw→标准值映射；
2. BL0942 原始寄存器在换算后没有作为原子快照对校准链路暴露；
3. 输出 ADC 原码、当前 PWM 原码、采样序号、采样年龄和错误计数未组成一致快照；
4. 当前 PWM 主要按线性公式计算，尚未把 11 点单调曲线安全接入正常控制链；
5. 当前分支不能假定已有完整的电流曲线、计量系数、双槽存储和 MQTT 校准会话实现；
6. 校准数据 Flash 地址必须结合当前链接布局、参数主备区和最新 MAP 重新审计后才能分配；
7. 现有协议的字节偏移、单位、字节序、校验算法和黄金样本必须冻结为一致性测试，禁止凭记忆重定义。
8. BL0942 的 `I/V/W/CF/FREQ` 原始字段当前没有缓存/MQTT接口，`I_FAST` 未参与工程值，频率字段还需核实实际赋值链；
9. 当前根目录旧校准执行文档包含 21 点和历史 MID=4 补偿，已不符合本次确认的 11 点/MID=1 基线，不能作为实现依据；
10. 当前上电 `softstar` 路径可能在首轮进入默认 100% 输出，且输出过流/过功率主动关断链需按当前源码重新核实；校准期间 MCU 复位不能仅依靠 MQTT 租约归零。

因此，“还需要读取 BL0942 命令”不是阻塞项；需要新增的是安全、可追踪、可回读的原始快照与校准配置闭环。

## 4. 总体架构

```text
tc 校准工作台
  ├─ 标准仪器驱动/本地仪器代理
  ├─ 校准会话编排与算法
  └─ MQTT 校准协议
          │
          ▼
CAT1 MQTT 路由
  └─ calibration_service
       ├─ 会话租约/互斥/安全关断
       ├─ MeterRaw 原子快照
       ├─ 11点 PWM 曲线临时应用
       ├─ 输入/输出采样校准
       └─ Flash A/B 事务存储 + CRC + 回读
```

校准服务不得直接替代现有保护与输出控制。过温、过压、过流、通信租约失效、复位和 OTA 的安全级别高于校准会话；任何保护触发都必须使会话失败并关断输出。

当前代码存在一个必须在 F2 前闭合的实机安全风险：若校准中 MCU 复位后正常启动路径重新渐升到 100%，后台租约已经来不及阻止瞬时满功率。实现必须在以下方案中选择并验证至少一项，且量产工站仍保留硬件急停/负载联锁：

- 持久化、带 CRC 和超时/恢复策略的 `calibration boot inhibit`，复位后保持 PWM=0，直到同一会话安全恢复或明确退出；
- 由工站硬件联锁控制电源使能/输入电源，复位时默认断开；
- 经安全评审的等效机制，证明复位、看门狗和棕断都不会恢复满功率。

校准 Raw PWM 上限必须由硬件验证的 50W 安全值决定；PWM 计数 1000 和 `HWMAX_OUTCUR=1680mA` 都只是当前软件参数，不能直接当作安全上限。若当前输出过流/过功率检测确实未启用，F2/HIL 前必须恢复、替代或通过工站硬件联锁补偿，不能只写风险说明。

## 5. 固件模块设计

### 5.1 原始采样快照

新增只读快照结构，字段至少包含：

```c
typedef struct {
    uint32_t seq;
    uint32_t tick_ms;
    uint32_t bl_i_rms_raw;
    uint32_t bl_v_rms_raw;
    uint32_t bl_i_fast_raw;
    int32_t  bl_power_raw;
    uint32_t bl_cf_raw;
    uint16_t bl_freq_raw;
    uint16_t vout_adc_raw;
    uint16_t iout_adc_raw;
    uint16_t pwm_raw;
    uint16_t valid_flags;
    uint16_t frame_error_count;
} calibration_raw_snapshot_t;
```

要求：

- BL0942 帧通过完整校验后发布 meter 快照，ADC/PWM 在自身采样链发布 output 快照；
- 两个来源分别带 `meterSeq/meterTickMs` 与 `adcSeq/adcTickMs`，MQTT 只做一次无撕裂聚合复制，不宣称二者物理同时采样；
- 采用临界区、双缓冲或 sequence-lock，禁止 MQTT 读取到任一来源的撕裂数据；
- 返回 `meterAgeMs/adcAgeMs`、有效位和错误计数；任一来源过期都不得用于拟合；
- 校准读取只消费缓存，不额外抢占 USART2 或发送并发 `58 AA`；
- 保留现有工程值上报，原始接口只在授权校准会话中开放。

### 5.2 校准上下文

配置必须绑定硬件上下文，至少包括：

- 协议/格式版本；
- MID、功率型号、额定电流、输出电流采样电阻；
- 硬件版本、固件版本、设备 SN；
- 11 点 PWM 曲线；
- BL0942 输入电压/电流/功率校准参数；
- 输出电压/电流 ADC 校准参数；
- 序列号、payload 长度、CRC、提交标志。

输出功率默认由校准后的输出电压和输出电流计算；只有现有协议明确提供独立输出功率字段时，才存独立参数。50W 与 100W 的 RS3 不同，配置上下文校验失败时必须拒绝激活，不能自动套用。

### 5.3 控制曲线与采样校准

- 控制曲线：11 点单调 LUT，点间分段线性插值；
- LUT 写入前校验等级固定、PWM 非递减、范围受限、100% 点不超过硬件允许值；
- 正常运行仍从现有百分比/目标电流入口进入保护和渐变链，不能用校准代码绕开；
- 校准模式可提供受限原始 PWM 调试，但必须受会话租约、最大值、斜率和紧急关断约束；
- 采样校准第一版采用 `工程值 = raw × gain + offset`；用标准仪器和 Raw 做最小二乘/稳健拟合；
- 只有线性模型在独立中点失败且现有协议允许时，才启用分段校正；不得擅自扩展量产协议；
- 控制精度和采样精度分别验证，不能用设备自身采样值证明设备自身输出正确。

### 5.4 Flash 事务存储

实施前必须输出当前分支的 Flash 占用表，核对：Boot、参数主区、参数备区、APP、OTA、运行参数以及候选校准页。当前可见候选 `0x08005C00..0x08005FFF` 与 `0x08007400..0x080077FF` 各只有 1KB，且分别位于一个 2KB 共享擦除页的后半部，并非独立 Flash 页；历史地址不能替代当前 MAP、整页数据所有者和擦除副作用审计。

推荐记录格式：

```text
magic | formatVersion | payloadLength | sequence
model/MID/contextCRC | payload | payloadCRC32 | headerCRC32 | commitFlag
```

事务流程：读取 A/B 最高有效序列 → 写非活动槽 → 整体回读校验 → 最后写提交标志 → 切换运行态。掉电、CRC 错、上下文不匹配时回退到上一份有效记录，且不得删除旧记录。

## 6. MQTT 校准契约

沿用现有 `SN/TM/SV/ID/CT/DT/ER` JSON 信封，建议使用隔离命名空间 `SV="cal"`，并保持 `CT="W"` 表示变更、`CT="R"` 表示读取；具体字段编码在 F0 通过现有协议原件和黄金报文冻结。

逻辑操作集：

| 操作 | 方向 | 必要结果 |
|---|---|---|
| `CAPABILITIES` | R | 协议版本、MID、型号、固件版本、最大 PWM、支持字段 |
| `BEGIN` | W | 校验安全前置条件，返回 `sessionId/nonce/leaseMs` 和当前配置摘要 |
| `HEARTBEAT` | W | 续租；ID、session、nonce 必须匹配 |
| `SET_POINT` | W | 设置协议等级或受限 PWM，返回实际 PWM 与状态 |
| `RAW` | R | 返回带 `seq/ageMs/valid` 的原始快照和当前工程值 |
| `STAGE_CONFIG` | W | 分包或整包暂存，校验长度、序号、上下文和 CRC，不提交 |
| `CONFIG` | R | 回读暂存/活动配置的版本、CRC 和精确 payload |
| `COMMIT` | W | 事务写入非活动槽、回读校验后切换，返回新序列和 CRC |
| `ABORT` | W | 立即 PWM=0，丢弃暂存，退出校准模式 |

强制语义：

- 所有写操作幂等，重复 `ID` 返回相同结果，不重复写 Flash；
- 同一设备同一时刻只有一个校准会话；普通调光写入与 Factory 变更在会话中必须拒绝或明确仲裁；
- ACK 必须带原请求 `ID`、`op`、`sessionId`、结果码和状态版本；
- `ER=0` 只表示该阶段完成，最终成功必须由工作台做匹配回读；
- MQTT 断开、租约超时、设备复位、保护触发、OTA 开始均执行安全关断并使会话进入 `ABORTED/FAULT`；
- payload 大于单包限制时使用固定大小分片、索引、总片数、总 CRC；乱序、缺片、重复片均可检测；
- 现有 11 点协议 payload 必须原样兼容。当前所知的 11×18/198 字节信息必须用协议原件和至少一组黄金文件确认后才能写死。

## 7. 实施阶段与门禁

### F0：协议和基线冻结

- 逐字节抄录现有校准协议：偏移、单位、缩放、符号、端序、校验、应答；
- 建立一份 50W 黄金配置及 encode/decode/CRC 往返测试；
- 输出 Flash 占用和候选槽审计；
- 固化错误码、租约和故障关断状态机；
- 门禁：评审通过，不写业务代码前先消除协议歧义。

### F1：只读原始快照与能力查询

- BL0942/ADC/PWM 原子快照；
- `CAPABILITIES/RAW` 查询；
- 帧校验、过期判定、并发读取测试；
- 门禁：不改变现有输出，主机测试和 ARM 语法检查通过。

### F2：校准会话与安全控制

- `BEGIN/HEARTBEAT/SET_POINT/ABORT`；
- 单设备互斥、租约、幂等、保护抢占、异常关断；
- 复位/看门狗/棕断后的 boot-inhibit 或经验证的工站硬件联锁；
- 核实并闭合当前输出过流/过功率关断链，不把注释掉的检测当作已有保护；
- 门禁：模拟 MQTT 丢失、超时、重复包、复位均回到 PWM=0。

### F3：11 点曲线和采样运行时

- LUT 校验、插值、临时应用和回退；
- 输入 U/I/P、输出 U/I 的系数应用；
- 保留现有渐变、保护和正常上报；
- 门禁：边界/溢出/单调/上下文不匹配测试通过。

### F4：配置暂存、双槽提交与回读

- `STAGE_CONFIG/CONFIG/COMMIT`；
- A/B 事务、CRC、掉电恢复、写次数约束；
- 门禁：故障注入证明任意写入中断均保留至少一份有效记录。

### F5：构建与软件集成

- 固件单元/协议/状态机测试；
- MQTT 模拟器与 `tc` 黄金报文联调；
- 两个 Keil target 的干净构建、MAP/ROM/RAM/Flash 地址审计；
- 门禁：不把 GCC 语法检查、旧 HEX 或主机测试当作 Keil 产物证据。

### F6：实机 HIL 与量产放行

- 50W 首板：36V、标称中点电压、56V；
- 11 点采集、10 个中点独立验证、重复性测试；
- MQTT/仪器掉线、工作台关闭、设备复位、掉电写入、配置 CRC 错误；
- 重启后配置版本、CRC、MID、RS3 上下文和输出复测；
- 50W 放行后，100W 只有在 MID、额定电流、输出范围和 50mΩ 参数确认并独立 HIL 后才可放行。

## 8. 测试门槛

| 类别 | 判定 |
|---|---|
| 10%/20%/30% 控制与采样 | 相对误差均 `<=2%` |
| 40%–100% 控制与采样 | 相对误差均 `<=1%` |
| 5%/15%/25% 中点 | 相对误差 `<=2%` |
| 35%–95% 中点 | 相对误差 `<=1%` |
| 0% | 使用待确认的绝对残余值和关断时间，不使用相对误差 |
| 稳定性 | 每点稳定窗口、样本数、标准差/峰峰值必须在工作台配置并留档 |
| 单调性 | 等级、PWM、标准输出均不得反向；允许相等仅限 0 点附近且需规则说明 |
| 仪器能力 | 标准仪器校准有效期内，组合不确定度建议不超过被测门槛的 1/4 |
| 成功语义 | ACK + 匹配回读 + 独立验证 + 掉电重启复测 |
| 安全 | 所有异常路径在规定时间内 PWM=0，且事件可审计 |

## 9. 尚待确认但不阻塞架构实施的参数

- 100W 的 MID、额定恒流值、输出电压范围和最大安全 PWM；
- 0% 点绝对残余电流/电压和最大关断时间；
- 现有校准 payload 的最终黄金文件、精确字节定义和校验向量；
- 仪器型号、通信介质、串口参数、校准证书/精度和电子负载可用模式；
- 50W 的 `HWMAX_OUTCUR=1680mA` 是软件回退上限还是经硬件验证的安全上限；
- 当前上电 soft-start 默认输出行为以及输出过流/过功率检测的量产安全处置；
- 最新 Keil MAP 下校准 A/B 槽的最终地址。

这些字段全部设计为配置/能力项。50W 的 F0–F5 可以先行；缺少 0% 门槛或仪器精度时，不允许自动出具“量产合格”；缺少 100W 参数时，不允许把 50W 配置复制到 100W。
