# 历史实现证据：旧 Profile / Context / CAL_MQTT_V2

> **状态：LEGACY IMPLEMENTATION EVIDENCE / 不得作为目标规范**

本文件只用于记录目标分支在旧设计阶段已经实现过哪些内容、哪些测试曾经通过。它不能作为后续功能开发的设计输入。

## 1. 当时已经实现的旧内容

历史实现曾包含：

- 50W旧默认 `SET_OUTCUR=890mA`；
- HWMAX 与 Product Profile 最大电流共用 1680mA；
- 198B 11点旧表；
- Storage Record Format 3；
- `CAL_MQTT_V2`；
- Profile Context 绑定固定校准电压、SET_OUTCUR、`calibratedMaxCurrentMa`；
- 多功率 Profile Catalog；
- 旧 Calibration A/B 1KiB候选槽；
- Host 测试和 V2 fixture。

这些内容说明当前代码为什么存在对应模块和测试，不代表应该保留这些业务规则。

## 2. 当前已经改变的目标口径

50W目标改为：

```text
Hardware Max       = 1680mA
Default HWMAX      = 1400mA
Default SET_OUTCUR = 893mA
RS3                = 120mΩ
```

同时：

- Calibration 不绑定运行 SET_OUTCUR；
- Calibration 不绑定运行输出电压；
- `calibratedMaxCurrentMa` 不作为普通运行授权；
- 无 Calibration 仍然正常运行；
- 无 Calibration 使用原 PWM + OP_PWM_OFFSET；
- 目标 MQTT 为 Protocol V3；
- 设备 CAP 只返回当前产品；
- Flash 改成完整2KiB物理页 Owner 的 Config/Calibration/Runtime A/B；
- 上位机保持多功率通用。

## 3. 历史测试怎么使用

旧 Host Tests、`CAL_MQTT_V2` fixtures 和旧 CRC 测试可以继续用于：

- 确认 Legacy 行为；
- 做迁移回归；
- 防止误删仍需要的底层 codec 能力。

但它们**不能作为新 Protocol V3 的通过条件**。如果旧测试与新目标业务逻辑冲突，应重写/替换测试，而不是为了让旧测试继续通过而保留废弃设计。
