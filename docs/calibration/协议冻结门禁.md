# 量产校准协议冻结门禁

状态：`BLOCKED`（仅记录已确认边界，不提供可互通的 codec）。

## 已确认的产品边界

- 首期只启用 50W：`MID=1`、额定恒流 `890mA`、输出范围 `36–56V`、`RS3=120mΩ`。
- 校准等级固定为 `0/20/40/.../200`，对应 `0%/10%/.../100%`，共 11 点。
- `<=30%` 的控制与采样误差门槛为 `2%`，`>30%` 为 `1%`；0% 必须使用单独的绝对残余值和关断时间门槛。
- 100W 只记录 `RS3=50mΩ`，MID、额定电流、输出范围和安全上限未确认，禁止启用量产配置。

## 当前阻断项

当前 CAT1 和 tc 工作树均没有权威校准 payload 原件、编解码实现、黄金 `.cal.bin` 或对应人可读值。`11×18/198` 只能作为外部线索，不能推导长度、字段、端序、校验、承载格式或分片规则。

因此本分支暂不实现：

- 真实校准二进制 encode/decode/CRC；
- `SV=cal` 的线协议字段映射和错误码复用；
- `STAGE_CONFIG/COMMIT` 的设备写入；
- 任何“ACK 即成功”的工作台结论。

## 解除门禁所需证据

1. 权威协议原件、发布版本和来源章节；
2. 至少一份真实黄金 payload 及对应字段值；
3. 真实 MQTT 请求、业务 ACK、精确回读三组抓包；
4. 每个字段的 offset、长度、符号、端序、单位、缩放、范围和校验覆盖表；
5. 单字节变异、encode 与黄金字节完全一致、decode 已知值一致的测试结果。

获得上述证据后，CAT1 C 测试和 tc Java 测试必须消费同一份只读 fixture/manifest。没有证据前，接口可以存在，但 codec 和 commit 必须显式返回“不可用”。
