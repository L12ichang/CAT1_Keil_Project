# 产品 Profile、运行额定电流与 CAL_MQTT_V2

状态：`CAL_MQTT_V2_FROZEN / FIRMWARE_HOST_VERIFIED / CLIENT_CROSS_TEST_PENDING`。

## 三层口径

1. 编译期产品 Profile 是普通命令不可越权的硬件能力，包含型号、MID、功率、I-V、RS3、HWMAX、绝对失效值和电压边界。
2. `SET_OUTCUR` 是可命令修改并持久化的单台设备运行额定电流，即 100% 调光设定值。50W 的 890mA 只是默认值。
3. `brightness` 是 0–100% 运行比例，目标电流为 `SET_OUTCUR × brightness / 100`。固定校准电压只绑定校准上下文，不锁死 SET_OUTCUR。

HWMAX、MID 和 RS3 只接受与当前编译 Profile 完全相等的工厂回写；`DATA_POINT_ID_SET_SETCUR/onSet_setcur_value` 保留并统一走 Profile 门禁。

## SET_OUTCUR 原子校验

绑定电压使用0.1V。写入必须同时满足25.0–56.0V、非零、低于绝对失效值、不超过 HWMAX/I-V/功率包络和已提交 `calibratedMaxCurrentMa`。58.0V特殊测试点不得绑定正式校准。失败不改RAM、不写Flash；绑定电压变化后旧表上下文不匹配，普通非零输出失败关闭。

50W功率容差保守为0‰。`SV=prop` 使用 ER 20–30 区分 Profile、电压、零电流、I-V、功率、HWMAX、绝对失效、会话占用、校准上限缺失和超过上限；旧数据点协议只能返回既有通用参数错误。

## 校准上下文和198字节表

基础表仍为11点×18字节=198字节；业务点0/10/.../100%，线值0/20/.../200，多字节字段大端，不增加多电压二维表。

线上 `DT.profileContext` 固定字段为：

- `contextVersion=1`
- `profileId`（JSON number）和 `modelCode`（JSON string）
- `profileVersion` 和无符号数值 `profileFingerprint`
- `calibrationVoltage01V`
- `configuredRatedCurrentMa`
- `calibratedMaxCurrentMa`
- `tableCrc32`

`DT.profileBindingCrc32` 与 context 并列。CRC32/IEEE 输入固定为大端：`u8 contextVersion, u16 profileId, u16 profileVersion, u32 profileFingerprint, u16 calibrationVoltage01V, u16 configuredRatedCurrentMa, u16 calibratedMaxCurrentMa, u32 tableCrc32`。modelCode不进CRC，但必须逐字匹配编译Profile。

首次 BEGIN 的 calibrated max/table CRC 为0；STAGE_CONFIG及以后使用198字节表CRC和表顶点导出的非零 calibrated max。上下文、SET_OUTCUR、Profile、绑定电压或CRC不匹配均失败关闭。表100%点当前必须覆盖50W理论上限的95%；真实硬件跨 SET_OUTCUR 精度仍需电子负载验证。

## CAL_MQTT_V2

请求 Topic 为 `MS/{SN}/plt2dev`，响应为 `MS/{SN}/dev2plt`；Envelope 保持 `SN/SV="cal"/ID/CT/DT`。每个请求的 `DT.protocolVersion` 必须为数字2。

CAPABILITIES 固定报告：

- `protocolVersion=2, protocolFrozen=true, driverProtocolVersion=1`
- `tablePoints=11, levelStep=20, profilesCodec="PROFILE_CSV_V1", profilesCsv, activeProfile`
- `firstCalibrationAllowed, runtimeNonzeroOutputAllowed, calibrationNonzeroOutputAllowed`
- `configuredRatedCurrentWriteReadbackAvailable, validationPercentOutputAvailable, commitAvailable, safetyReady, blockCode`

不再发布含义模糊的 `nonzeroOutputAllowed`。首次校准允许不代表普通运行输出已放行。

操作集合固定为 `CAPABILITIES, BEGIN, HEARTBEAT, SET_POINT, RAW, STAGE_CONFIG, APPLY, SET_VALIDATION_PERCENT, READBACK, COMMIT, ABORT, RELEASE`。SET_POINT只接受0/20/.../200；SET_VALIDATION_PERCENT只接受1..99，按已APPLY表临时反查输出且不改表。STAGE_CONFIG使用 `payloadHex`；响应统一放入 `DT.readback.profileContext/profileBindingCrc32/payloadHex/tableCrc32`，提交回显 `committed/committedGeneration/committedTableCrc32/committedProfileBindingCrc32`。

四组共享JSON与SHA256位于 `protocol/fixtures/CAL_MQTT_V2`。固件主机测试用真实C handler解析请求并核对响应；客户端必须无格式变化复制并用TS解析固件响应后，才完成双向验收。
